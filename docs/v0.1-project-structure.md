# Backend v0.1: Project Structure

## Goal

Get the project into its final shape: the right dependencies, a working `application.yml`, the layered package folders, and one tiny endpoint to prove the pipeline works. There's no business logic yet.

## Prerequisites

None. This is the starting point.

## Steps

### 1. Dependencies

Spring Boot 4 split the old "web" starter into smaller modules. Replace the current `dependencies { }` block with only what v0.1 to v0.4 need. Security and the CSV/Excel libraries are added later (v0.5 and v0.8). If you added Spring Security now, every endpoint would immediately require a login.

```groovy
dependencies {
    implementation 'org.springframework.boot:spring-boot-starter-webmvc'
    implementation 'org.springframework.boot:spring-boot-starter-data-jpa'
    implementation 'org.springframework.boot:spring-boot-starter-validation'
    implementation 'org.springframework.boot:spring-boot-h2console'
    implementation 'org.springdoc:springdoc-openapi-starter-webmvc-ui:3.0.0'
    runtimeOnly 'com.h2database:h2'

    testImplementation 'org.springframework.boot:spring-boot-starter-webmvc-test'
    testImplementation 'org.springframework.boot:spring-boot-starter-data-jpa-test'
    testRuntimeOnly 'org.junit.platform:junit-platform-launcher'
}
```

| Dependency                            | Why                                                                                                                                  |
| ------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------ |
| `starter-webmvc`                      | REST controllers, embedded Tomcat, Jackson 3 JSON                                                                                    |
| `starter-data-jpa`                    | Hibernate 7 + Spring Data repositories                                                                                               |
| `starter-validation`                  | `@NotBlank`, `@Positive`, ... on request DTOs                                                                                        |
| `spring-boot-h2console`               | the `/h2-console` web UI (it's a separate module in Boot 4)                                                                          |
| `springdoc-openapi-starter-webmvc-ui` | Swagger UI. Use the 3.x line (the one that supports Boot 4) and check [springdoc.org](https://springdoc.org) for the latest version. |
| `h2`                                  | in-memory database                                                                                                                   |
| `*-test` starters                     | JUnit 5, AssertJ, Mockito, MockMvc, `@DataJpaTest`                                                                                   |

Then refresh Gradle in your IDE.

### 2. `application.yml`

The current file has `server:` indented under `spring:`, so the port setting is ignored. Delete `application.yaml` and create `application.yml`:

```yaml
server:
  port: 8080

spring:
  application:
    name: ims
  datasource:
    url: jdbc:h2:mem:ims;DB_CLOSE_DELAY=-1
    username: sa
    password:
  jpa:
    open-in-view: false
    show-sql: true
    hibernate:
      ddl-auto: create-drop
    properties:
      hibernate:
        format_sql: true
  h2:
    console:
      enabled: true
      path: /h2-console

springdoc:
  swagger-ui:
    path: /swagger-ui.html

app:
  seed:
    enabled: true
```

What these settings do:

- `ddl-auto: create-drop`: Hibernate creates the tables from your entities at startup and drops them at shutdown. Your entity classes _are_ your schema, so put constraints on them carefully.
- `open-in-view: false`: lazy relationships can't be loaded during JSON rendering. This forces you to map to DTOs inside the service, which is the right habit.
- `DB_CLOSE_DELAY=-1`: keeps the in-memory database alive for as long as the JVM runs.
- `app.seed.enabled`: your own property, used by the seeder in v0.3.

### 3. Packages

Create these empty packages under `com.example.ims` (in IntelliJ: right-click, New, Package):

```
config/ controller/ dto/ entity/ exception/ repository/ security/ service/
```

Also create `src/main/resources/seed/` and the test packages `controller/`, `repository/`, `service/` under `src/test/java/com/example/ims/`.

Keep `ImsApplication.java` in the root package `com.example.ims`. Component scanning starts from there, so every class must live in that package or below it.

### 4. `PingController`

This is your first controller. Its job is to prove that routing and JSON rendering work.

- Annotate it with `@RestController` and `@RequestMapping("/api")`.
- `GET /api/ping` returns `Map.of("status", "ok", "time", Instant.now())`.

### 5. `.gitignore`

Make sure `build/`, `bin/` (generated by VS Code), `.gradle/` and `*.mv.db` are ignored. The `bin/` folder that is already there is compiler output, so you can delete it.

## Done checklist

- [x] `.\gradlew.bat bootRun` starts without errors and logs `Tomcat started on port 8080`
- [x] http://localhost:8080/api/ping returns `{"status":"ok", ...}`

- [x] http://localhost:8080/h2-console connects with JDBC URL `jdbc:h2:mem:ims`, user `sa`, empty password
- [x] `.\gradlew.bat test` passes (the generated `ImsApplicationTests` context test)
