# Backend v0.6: User Management

## Goal
Admins manage all users. Managers manage the staff in their own branch. Every user can change their own password. Password hashes never leave the server.

## Prerequisites
Backend v0.5 is done.

## Files

| Layer | Path |
|---|---|
| dto | `dto/UserCreateRequest.java`, `dto/UserUpdateRequest.java`, `dto/ChangePasswordRequest.java`, `dto/ResetPasswordRequest.java`, `dto/UserResponse.java` |
| service | `service/UserService.java` |
| controller | `controller/UserController.java` |

## Steps

### 1. DTOs
- `UserCreateRequest(@NotBlank @Size(min=3,max=50) @Pattern("[a-z0-9._-]+") username, @NotBlank @Size(min=8) password, @NotBlank fullName, @NotNull Role role, Long branchId)`
- `UserUpdateRequest(@NotBlank fullName, @NotNull Role role, Long branchId, boolean active)`. The username can't be changed.
- `ChangePasswordRequest(@NotBlank currentPassword, @NotBlank @Size(min=8) newPassword)`
- `ResetPasswordRequest(@NotBlank @Size(min=8) newPassword)`
- `UserResponse(id, username, fullName, role, branchId, branchCode, active, createdAt)`. There is **no** password field.

### 2. `UserService` rules
| Method | Rules |
|---|---|
| `List<UserResponse> list(Long branchId, Role role)` | ADMIN can filter freely. MANAGER always gets their own branch. |
| `UserResponse get(Long id)` | MANAGER can only view users in their own branch |
| `UserResponse create(UserCreateRequest r)` | unique username (409); hash the password; ADMIN must not have a branch, others must; MANAGER can only create `STAFF` in their own branch |
| `UserResponse update(Long id, UserUpdateRequest r)` | same role/branch rules; users can't change their own role or deactivate themselves; MANAGER can only edit STAFF in their branch |
| `void deactivate(Long id)` | soft delete; can't deactivate yourself; never deactivate the last active ADMIN |
| `void changeOwnPassword(ChangePasswordRequest r)` | check `currentPassword` with `passwordEncoder.matches` and return 400 if it's wrong |
| `void resetPassword(Long id, ResetPasswordRequest r)` | ADMIN for anyone; MANAGER for staff in their branch |

Put these checks in private helper methods such as `assertCanManage(User target)` and `assertValidRoleBranch(Role, Long branchId)`, so each public method reads like a list of rules.

Also refactor the seeder to create users through `UserService.create` (running as the system user), so seeded users get the same validation.

### 3. `UserController` (`/api/users`)
| HTTP | Path | `@PreAuthorize` |
|---|---|---|
| GET | `/` with `branchId`, `role` | `hasAnyRole('ADMIN','MANAGER')` |
| GET | `/{id}` | `hasAnyRole('ADMIN','MANAGER')` |
| POST | `/` | `hasAnyRole('ADMIN','MANAGER')` |
| PUT | `/{id}` | `hasAnyRole('ADMIN','MANAGER')` |
| DELETE | `/{id}` | `hasAnyRole('ADMIN','MANAGER')` |
| PUT | `/{id}/password` | `hasAnyRole('ADMIN','MANAGER')` (reset) |
| PUT | `/me/password` | authenticated (change own) |

Map `/me/password` before `/{id}/password`, or use a distinct path. Spring matches the literal `me` first, but keep the paths unambiguous anyway.

## API contract
`POST /api/users` (as `manager`)
```json
{ "username": "kl.staff2", "password": "Welcome@123", "fullName": "Second KL Staff", "role": "STAFF", "branchId": 2 }
```
`201` returns a `UserResponse`. The same request with `"role": "MANAGER"` returns 403.

## Done checklist
- [ ] `manager` lists only KL01 users; `admin` lists all users
- [ ] `manager` creates a STAFF user in KL01 (201), and gets 403 for a STAFF user in PG01 or for a MANAGER
- [ ] Creating an ADMIN with a branch, or a STAFF without one, returns 400
- [ ] A deactivated user can't log in (401)
- [ ] Changing your own password with the wrong current password returns 400; after a successful change, the new password works
- [ ] No response anywhere contains `passwordHash`
- [ ] You can't deactivate yourself, or the last admin
