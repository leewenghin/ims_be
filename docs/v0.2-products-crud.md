# Backend v0.2: Products CRUD

## Goal
Build the first complete vertical slice: `Product` from entity to REST endpoint, with validation, consistent errors, search and paging. Every later module copies this pattern, so take your time here.

## Prerequisites
Backend v0.1 is done.

## Steps

### 1. `BaseEntity` (`@MappedSuperclass`)
Shared columns for every entity:
- `Long id` with `@Id @GeneratedValue(strategy = GenerationType.IDENTITY)`
- `Instant createdAt` with `@CreationTimestamp` and `@Column(nullable = false, updatable = false)`
- `Instant updatedAt` with `@UpdateTimestamp`

Give it getters, and no setter for `id`.

### 2. `Product` entity
`@Entity @Table(name = "product")`. Fields and constraints:

| Field | Type | Column rules |
|---|---|---|
| sku | String | `nullable = false, unique = true, length = 50` |
| barcode | String | `unique = true, length = 64` (nullable) |
| name | String | `nullable = false, length = 150` |
| description | String | `length = 1000` |
| category | String | `length = 80` |
| unit | String | `nullable = false, length = 20` (e.g. `pcs`, `box`, `kg`) |
| reorderLevel | int | `nullable = false`, default 0 |
| active | boolean | `nullable = false`, default true |

Add indexes in `@Table(indexes = { @Index(name = "idx_product_name", columnList = "name"), @Index(columnList = "category") })`.

JPA needs a `protected` no-args constructor. Add a public constructor or factory for the required fields, and a method like `update(ProductRequest r)` or individual setters.

Why `active` and not a real delete: once stock movements reference a product (v0.4), deleting it would break the history. A "delete" in this system is a **soft delete**.

### 3. `ProductRepository`
`interface ProductRepository extends JpaRepository<Product, Long>`
- `boolean existsBySku(String sku)`
- `boolean existsBySkuAndIdNot(String sku, Long id)`, used on update
- `Optional<Product> findBySku(String sku)`
- `Optional<Product> findByBarcode(String barcode)`
- A search query. Write it in JPQL with `@Query`:
  ```
  select p from Product p
  where p.active = true
    and (:q is null or lower(p.name) like lower(concat('%', :q, '%'))
                    or lower(p.sku)  like lower(concat('%', :q, '%')))
    and (:category is null or p.category = :category)
  ```
  Signature: `Page<Product> search(@Param("q") String q, @Param("category") String category, Pageable pageable)`

### 4. DTO records
- `ProductRequest(sku, barcode, name, description, category, unit, reorderLevel)` with validation: `@NotBlank @Size(max=50) sku`, `@NotBlank name`, `@NotBlank unit`, `@PositiveOrZero reorderLevel`, and `@Size` on the rest.
- `ProductResponse(id, sku, barcode, name, description, category, unit, reorderLevel, active, createdAt, updatedAt)` with `static ProductResponse from(Product p)`.
- `PageResponse<T>(List<T> content, int page, int size, long totalElements, int totalPages)` with `static <E, T> PageResponse<T> of(Page<E> page, Function<E, T> mapper)`.
  Return this instead of Spring's `Page`. Its JSON shape is stable and you control it.

### 5. `ProductService`
Annotate the class with `@Service @Transactional(readOnly = true)`. Mark the write methods `@Transactional`.

| Method | Rules |
|---|---|
| `PageResponse<ProductResponse> search(String q, String category, Pageable pageable)` | treat a blank `q` as null |
| `ProductResponse get(Long id)` | throws `NotFoundException("Product", id)` |
| `ProductResponse create(ProductRequest r)` | if `existsBySku`, throw `ConflictException("SKU already exists")`; trim strings; uppercase the SKU |
| `ProductResponse update(Long id, ProductRequest r)` | same uniqueness check, excluding its own id |
| `void deactivate(Long id)` | sets `active = false` |

You don't need to call `save()` after modifying an entity you loaded inside a transaction. Hibernate notices the change (dirty checking) and writes it on commit. Make sure you understand why.

### 6. `ProductController`
`@RestController @RequestMapping("/api/products")`

| HTTP | Path | Returns |
|---|---|---|
| GET | `/` with `q`, `category`, `page`, `size`, `sort` | `200 PageResponse<ProductResponse>` |
| GET | `/{id}` | `200 ProductResponse` |
| POST | `/` with `@Valid @RequestBody ProductRequest` | `201` + `Location: /api/products/{id}` |
| PUT | `/{id}` | `200 ProductResponse` |
| DELETE | `/{id}` | `204` |

Use `@PageableDefault(size = 20, sort = "name") Pageable pageable` for paging.

### 7. Exceptions and `GlobalExceptionHandler`
- `NotFoundException` and `ConflictException` extend `RuntimeException`.
- `GlobalExceptionHandler`: `@RestControllerAdvice` that extends `ResponseEntityExceptionHandler`. It returns `ProblemDetail`:
  - `NotFoundException` -> 404
  - `ConflictException` -> 409
  - `DataIntegrityViolationException` -> 409 "Constraint violated". This catches a race the uniqueness check missed.
  - Override `handleMethodArgumentNotValid` -> 400 with `problem.setProperty("errors", Map<field, message>)`.
- Add `spring.mvc.problemdetails.enabled: true` to `application.yml`, so Spring's built-in errors use the same format.
- Don't add a catch-all `@ExceptionHandler(Exception.class)` yet. In v0.5 it would swallow security exceptions.

## API contract

`POST /api/products`
```json
{ "sku": "SKU-001", "barcode": "9555012345678", "name": "A4 Paper 80gsm", "description": "500 sheets",
  "category": "Stationery", "unit": "ream", "reorderLevel": 10 }
```
`201 Created`
```json
{ "id": 1, "sku": "SKU-001", "barcode": "9555012345678", "name": "A4 Paper 80gsm", "description": "500 sheets",
  "category": "Stationery", "unit": "ream", "reorderLevel": 10, "active": true,
  "createdAt": "2026-10-29T07:00:00Z", "updatedAt": "2026-10-29T07:00:00Z" }
```
`400` on validation failure:
```json
{ "title": "Bad Request", "status": 400, "detail": "Validation failed",
  "errors": { "name": "must not be blank", "reorderLevel": "must be greater than or equal to 0" } }
```

## Done checklist
- [ ] Create, get, update, search and deactivate work in Swagger or `products.http`
- [ ] A duplicate SKU returns 409, not 500
- [ ] An empty body returns 400 with an `errors` map
- [ ] `GET /api/products/999` returns 404 as `ProblemDetail`
- [ ] A deactivated product no longer appears in search
- [ ] The H2 console shows the `product` table with unique constraints on `sku` and `barcode`
- [ ] Paging works: `?page=1&size=2&sort=sku,desc`
