# Backend v0.5: Authentication (JWT) and RBAC

## Goal
Every endpoint except login requires a valid JWT. Roles decide **what** a user can do, and the user's branch decides **where** they can do it. Movements record who made them.

## Prerequisites
Backend v0.4 is done.

## Steps

### 1. Dependencies
```groovy
implementation 'org.springframework.boot:spring-boot-starter-security'
implementation 'org.springframework.boot:spring-boot-starter-security-oauth2-resource-server'
testImplementation 'org.springframework.security:spring-security-test'
```
The resource server starter includes Nimbus, which handles signing and verifying JWTs. You don't need any other JWT library. In Boot 3 the starter was called `spring-boot-starter-oauth2-resource-server`. If Gradle can't resolve the Boot 4 name above, check the Boot 4 starter list.

### 2. `Role` and `User`
- `enum Role { ADMIN, MANAGER, STAFF }`
- `User extends BaseEntity`, mapped with `@Table(name = "app_user")`. `user` is a reserved word in H2.
  Fields: `username` (unique, 50), `passwordHash` (not null, 100), `fullName`, `role` (`@Enumerated(STRING)`), `branch` (`@ManyToOne LAZY`, nullable), `active`.
- Invariant, checked in the service: `branch == null` if and only if `role == ADMIN`.
- `UserRepository.findByUsername(String)`

### 3. Seed users
`seed/users.json`. These are plain-text passwords for development only. The seeder hashes them.
```json
[
  { "username": "admin",   "password": "Admin@123",   "fullName": "System Admin",  "role": "ADMIN",   "branch": null },
  { "username": "manager", "password": "Manager@123", "fullName": "KL Manager",    "role": "MANAGER", "branch": "KL01" },
  { "username": "staff",   "password": "Staff@123",   "fullName": "KL Staff",      "role": "STAFF",   "branch": "KL01" },
  { "username": "pgstaff", "password": "Staff@123",   "fullName": "Penang Staff",  "role": "STAFF",   "branch": "PG01" }
]
```
The `pgstaff` user lets you test that one branch can't see another. Seed users **after** branches, and before opening stock.

### 4. JWT configuration
`application.yml`:
```yaml
app:
  jwt:
    secret: ${JWT_SECRET:change-me-to-a-32+-byte-random-dev-secret-value!!}
    expiry: PT8H
    issuer: ims
```
HS256 needs a secret of **at least 32 bytes**. Read it into a `@ConfigurationProperties("app.jwt") record JwtProperties(String secret, Duration expiry, String issuer)`.

### 5. `SecurityConfig`
Annotate it with `@Configuration @EnableMethodSecurity`. Beans:
- `PasswordEncoder`: `PasswordEncoderFactories.createDelegatingPasswordEncoder()`. It uses BCrypt and stores the hash with a `{bcrypt}` prefix.
- `SecretKey`: `new SecretKeySpec(secret.getBytes(UTF_8), "HmacSHA256")`
- `JwtEncoder`: `new NimbusJwtEncoder(new ImmutableSecret<>(key))`
- `JwtDecoder`: `NimbusJwtDecoder.withSecretKey(key).macAlgorithm(MacAlgorithm.HS256).build()`
- `AuthenticationManager`: a `ProviderManager` wrapping a `DaoAuthenticationProvider(userDetailsService)` that uses the password encoder
- `JwtAuthenticationConverter`: a `JwtGrantedAuthoritiesConverter` with `setAuthoritiesClaimName("role")` and `setAuthorityPrefix("ROLE_")`
- `SecurityFilterChain`:
  - `csrf` disabled. That's safe here because the API uses bearer tokens, not cookies.
  - `sessionManagement(STATELESS)`
  - `permitAll`: `POST /api/auth/login`, `/swagger-ui/**`, `/v3/api-docs/**`, `/h2-console/**`, `/api/ping`
  - Everything else is `authenticated()`
  - `oauth2ResourceServer(o -> o.jwt(j -> j.jwtAuthenticationConverter(converter)))`
  - `headers(h -> h.frameOptions(f -> f.sameOrigin()))`, so the H2 console (which uses frames) still works

### 6. `DbUserDetailsService implements UserDetailsService`
It loads the `User` by username and returns `org.springframework.security.core.userdetails.User.withUsername(...).password(hash).roles(role.name()).disabled(!active).build()`. A deactivated user can then never log in.

### 7. `JwtService`
`String issue(User user)` builds `JwtClaimsSet` with these claims: `iss`, `sub` = username, `iat`, `exp` = now + expiry, `role` = `"MANAGER"`, `branchId` = 2 (omit it for ADMIN), `name` = full name. Encode it with `JwsHeader.with(MacAlgorithm.HS256)`.

### 8. `AuthService` and `AuthController`
- `POST /api/auth/login` takes `LoginRequest(@NotBlank username, @NotBlank password)` and returns `LoginResponse(token, expiresAt, MeResponse user)`.
  - Call `authenticationManager.authenticate(new UsernamePasswordAuthenticationToken(u, p))`. A wrong password throws `BadCredentialsException`, which you map to 401 "Invalid username or password". Use the same message for an unknown username.
- `GET /api/auth/me` returns `MeResponse(id, username, fullName, role, branchId, branchCode)`.

### 9. `CurrentUser` (`@Component`)
It reads `SecurityContextHolder.getContext().getAuthentication()`. When the user is logged in, the principal is a `Jwt`. Methods:
- `String username()`, `Role role()`, `Optional<Long> branchId()`, `boolean isAdmin()`
- It returns `"system"` / `ADMIN` when nobody is logged in, so the seeder still works.

### 10. `BranchAccessGuard` (`@Component`)
- `void check(Long branchId)`: does nothing for ADMIN. Otherwise, if `branchId` is not the user's own branch, it throws `BranchAccessDeniedException` (403).
- `Long resolve(Long requestedBranchId)` is for list endpoints. ADMIN gets `requestedBranchId` (which may be null, meaning all branches). Everyone else always gets their own branch id, whatever they requested.

### 11. Apply the rules
Role checks go on the controllers with `@PreAuthorize`. Branch checks go in the services.

| Endpoint | `@PreAuthorize` | Branch check in service |
|---|---|---|
| `POST/PUT/DELETE /api/branches/**` | `hasRole('ADMIN')` | |
| `GET /api/branches` | authenticated | |
| `POST/PUT/DELETE /api/products/**` | `hasAnyRole('ADMIN','MANAGER')` | |
| `GET /api/inventory` | authenticated | `branchId = guard.resolve(branchId)` |
| `POST /api/movements/receipts`, `/issues` | authenticated | `guard.check(r.branchId())` |
| `POST /api/movements/adjustments` | `hasAnyRole('ADMIN','MANAGER')` | `guard.check(r.branchId())` |
| `POST /api/movements/transfers` | `hasAnyRole('ADMIN','MANAGER')` | `guard.check(r.fromBranchId())` (only the source branch) |
| `GET /api/movements` | authenticated | `filter.branchId = guard.resolve(...)` |

In `StockMovementService.record`, set `createdBy = currentUser.username()`.

### 12. Error mapping
- 401: the resource server already returns it, with a `WWW-Authenticate` header.
- 403: `AccessDeniedException` (thrown by `@PreAuthorize`) and `BranchAccessDeniedException` both map to 403 `ProblemDetail` in `GlobalExceptionHandler`.
- Do not add an `@ExceptionHandler(Exception.class)` that would catch `AccessDeniedException` and turn it into a 500.

### 13. Swagger with a token
Create `config/OpenApiConfig` with `@SecurityScheme(name = "bearer", type = HTTP, scheme = "bearer", bearerFormat = "JWT")` and `@OpenAPIDefinition(security = @SecurityRequirement(name = "bearer"))`. The Swagger "Authorize" button then works.
