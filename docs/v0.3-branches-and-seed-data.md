# Backend v0.3: Branches and Seed Data

## Goal
1. Repeat the CRUD pattern on `Branch`, this time without looking at the v0.2 guide too much.
2. Load starting data from JSON files at startup with a `DataSeeder`, so the app is never empty after a restart.

## Prerequisites
Backend v0.2 is done.

| Layer | Path |
|---|---|
| entity | `entity/Branch.java` |

| service | `service/BranchService.java` |
| controller | `controller/BranchController.java` |

| resources | `seed/branches.json`, `seed/products.json` |

## Steps

### 1. Branch module
`Branch extends BaseEntity`:

| Field | Rules |
|---|---|
| code | `nullable = false, unique = true, length = 20`; stored in uppercase (`HQ`, `KL01`) |
| name | `nullable = false, length = 120` |
| address | `length = 255` |
| active | default true |

Endpoints (`/api/branches`) follow the products pattern: list (no paging needed, return `List<BranchResponse>`, optional `?activeOnly=true`), get, create (409 on duplicate code), update, and DELETE as a soft delete returning 204.

Rule: don't allow deactivating a branch that still has stock. You can't enforce this yet. Leave a `// TODO v0.4` comment and add the check when `StockLevel` exists.

### 3. `DataSeeder`
`@Component` that implements `ApplicationRunner` and is annotated with `@ConditionalOnProperty(name = "app.seed.enabled", havingValue = "true")`.

Responsibilities:
- `run(ApplicationArguments args)` is annotated with `@Transactional`. If `branchRepository.count() > 0`, return early so the seeder stays safe if you later switch to a file database.
- Read each file with an injected Jackson 3 mapper and `ClassPathResource`:
  ```java
  // imports: tools.jackson.databind.json.JsonMapper, tools.jackson.core.type.TypeReference
  List<BranchSeed> seeds = jsonMapper.readValue(new ClassPathResource("seed/branches.json").getInputStream(),
                                                new TypeReference<List<BranchSeed>>() {});
  ```
- Define small private records inside `DataSeeder` (`BranchSeed`, `ProductSeed`) that match the JSON. Don't reuse your request DTOs, because seed files and the API will drift apart.
- Seed **through the services** (`branchService.create(...)`, `productService.create(...)`), not the repositories. That way seed data passes the same validation and normalization as API data.
- Log a summary, for example `Seeded 3 branches, 10 products`.

Boot 4 uses **Jackson 3**. Its packages are `tools.jackson.*`. Annotations like `@JsonProperty` are still `com.fasterxml.jackson.annotation.*`. If your IDE suggests `com.fasterxml.jackson.databind.ObjectMapper`, that's the old Jackson 2. Inject `JsonMapper` instead.

Order matters, and will grow over the versions: branches, products, (v0.4) opening stock, (v0.5) users, (v0.8) API clients.

## Done checklist
- [ ] Startup logs `Seeded 3 branches, 10 products`
- [ ] `GET /api/branches` returns the 3 branches, `GET /api/products` returns the 10 products
- [ ] Setting `app.seed.enabled: false` starts the app with empty tables
- [ ] Duplicate branch code returns 409; a lowercase code is stored in uppercase
- [ ] Deleting a branch deactivates it (`active=false`) and the row still exists
